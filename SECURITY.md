# Security Policy

## Supported Versions

This repository is pre-1.0. Security fixes target the current `main` branch until a stable release line exists.

## Reporting A Vulnerability

Please use GitHub private vulnerability reporting if it is enabled for the repository. If private reporting is not available, open a minimal public issue that says a security report is needed without publishing exploit details, local paths, secrets, or private project contents.

Reports should include the affected package or app, version or commit, reproduction steps, expected impact, and any safe mitigation you already tested.

## Scope

Security reports for the reusable engine libraries, file-system snapshot storage, export handling, and desktop sandbox are in scope. Reports about intentionally local test fixtures, non-shipping harnesses, or the future MCP host driver should identify that context clearly so they are routed correctly.
